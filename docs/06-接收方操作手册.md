# Parpar B2B 独立站 · 接收方操作手册

> 适用：网站交接后由非技术人员独立运营（改产品、写博客、改文案、查询盘）
> 前置：需要 GitHub 账号 + 电脑能访问代码（或让开发方代改，见"四、找人代改"）
> 目录：E:\parpar-b2b（源码）；线上：https://parpareg.com（Vercel 自动部署）

---

## 零、快速认识网站结构（3 分钟）

```
src/
├── lib/
│   ├── products.ts      ← 5 款产品的所有数据（名称/规格/卖点/图片/FAQ）★改产品在这
│   ├── posts.ts         ← 6 篇博客文章（含英文+阿语）★写博客在这
│   └── useTranslation.ts ← 全站界面文字（中英文对……英文/阿语对照字典）★改按钮/菜单文字在这
├── app/
│   ├── [lang]/          ← 所有页面（/en 英文版、/ar 阿语版共用一套文件）
│   └── api/inquiry/     ← 询盘接口（一般不用动）
└── components/          ← 通用组件（页头/页脚/表单等）
```

**核心规则：改数据（产品/博客）→ 网站英文和阿语版都会自动更新。**

## 一、改产品（新增/修改/下架）

文件：`src/lib/products.ts`（每款产品是一个对象，结构固定）

### 1.1 修改现有产品（如改名字、价格说明、规格）
找到对应产品对象（按 `id` 如 `P001`），改对应字段：
| 字段 | 说明 |
|---|---|
| `name` / `nameAr` | 英文名 / 阿语名 |
| `category` | 分类（如 "Cockroach Control"） |
| `description` / `descriptionAr` | 产品描述（建议 3-5 行） |
| `features` | 卖点列表（`feature` + `featureAr`） |
| `specs` | 规格参数表（`label`/`labelAr` + `value`/`valueAr`） |
| `image` | 图片路径（`/images/xxx.jpg`，图片放 `public/images/`） |
| `faqs` | 产品 FAQ（双语，用于页面 FAQ 区块） |

### 1.2 新增产品
1. 复制一个现有产品对象，改 `id`（如 P006）、所有字段、图片
2. 在 `export const products: Product[] = [...]` 数组里加进去
3. 产品详情页 /products/{slug} 会自动生成（slug 由 id 推导）

### 1.3 下架产品
从数组里删掉该对象即可（页面和 sitemap 会自动移除）。

## 二、写博客（新增文章）

文件：`src/lib/posts.ts`（每篇文章一个对象）

### 新增文章模板（复制改）
```ts
{
  slug: "your-post-slug",              // 网址后缀，小写+连字符
  title: "English Title",
  description: "Short summary for search engines (150 chars)",
  category: "Category Name",
  date: "2026-08-26",
  image: "/images/blog/xxx.jpg",
  contentHtml: `...英文正文 HTML...`,
  // 阿语版（必填，双语站缺一不可）：
  titleAr: "العنوان بالعربية",
  descriptionAr: "ملخص قصير بالعربية",
  categoryAr: "الفئة",
  contentHtmlAr: `...阿语正文 HTML...`,
}
```
> 正文用 HTML 写：`<h2>`小标题、`<p>`段落、`<ul><li>`列表、`<a href="/products/xxx">`内链（阿语正文内链要写 `/ar/products/xxx`）。

### 文章发布后
- 博客列表页 /blog、详情页、sitemap 自动更新
- **重要**：写完后要在 Google Search Console 提交更新（见"五、上线流程"）

## 三、改界面文字（菜单/按钮/页脚）

文件：`src/lib/useTranslation.ts`（一个大对象，`key: 阿语` / `key: 英语` 两组）

- 找你要改的文字的 key（如 `footer.about`），改阿语组和英语组两处
- **不能删 key、不能改 key 名**（组件靠 key 取文字）；新增页面文案也要成对加 key
- 页面级大段文案（如 About、政策页）直接写在 `src/app/[lang]/` 对应页面的 tsx 里（有 `isAr ? "阿语" : "英语"` 的判断）

## 四、找人代改（不想碰代码时的办法）

把需求写成表格发给开发方，例如：
> 「产品 P002 的描述第一句改成：……；新增一款产品 P006：蟑螂诱饵盒，图在附件，规格如下……；博客新增一篇标题为……的英文+阿语文章」
开发方改完会 git push，Vercel 自动部署上线。

## 五、上线流程（改完代码后）

1. 改完代码保存
2. 命令行（在 E:\parpar-b2b 目录）：
   ```
   npm run build        ← 构建检查（必须通过）
   git add -A && git commit -m "描述改动"
   git push             ← push 后 Vercel 自动部署（约 1-2 分钟）
   ```
3. 打开 https://parpareg.com 刷新确认改动生效（注意浏览器缓存，可开无痕窗口看）
4. 重要改动后在 Google Search Console → Sitemap 提交 `https://parpareg.com/sitemap.xml` 刷新索引

## 六、查询盘（收到客户询价）

- 客户提交表单 → 邮件通知到 **support@parpareg.com**（Vercel 后台环境变量 `NOTIFICATION_EMAIL` 控制）

## 七、常见问题

| 问题 | 处理 |
|---|---|
| 改了产品不生效 | 确认保存了 products.ts；`npm run build` 无报错；看线上是否部署完成（Vercel 部署中页面会显示状态） |
| 阿语版没变 | 确认改了 `nameAr`/`descriptionAr` 等带 Ar 的字段 |
| 图片不显示 | 图片要放 `public/images/`，路径以 `/images/` 开头 |
| 想加页面 | 复制 `src/app/[lang]/` 下现有页面目录改名，改内容，**页面链接要加进 Footer/Header 和 sitemap.ts** |
| 邮件收不到询盘 | 先查垃圾邮件；再确认 Vercel 后台 `NOTIFICATION_EMAIL` 环境变量正确 |
